# Contributing

## Commit messages

Use this format for commit messages:

```text
[category]: [action/detail]
```

Use a short, lowercase category that describes the change. After the colon, briefly state what the commit does, starting with an action verb where possible. Keep each commit focused on one logical change.

Examples:

- `fix: edit Dockerfile so all dependencies are installed`
- `docs: add changelog details`
- `ecosystem: update how training is completed`

Common categories:

- `fix` — correct a bug or unexpected behavior
- `feat` — add functionality
- `docs` — change documentation
- `test` — add or update tests
- `refactor` — restructure code without changing behavior
- `build` — change build configuration or dependencies
- `ecosystem` — change integrations, workflows, or the project environment
